# Architecture Decisions (DESIGN.md)

## Folder Layout
The repository uses a single unified monorepo approach for both the frontend (React + Vite) and the lightweight backend server (Express).
- **`src/`**: Contains all frontend components (`App.tsx`, `TerminalView.tsx`, etc.) and basic styling (`index.css`).
- **`src/backend/`**: Groups backend-related modules (e.g. `auth/`, `git/`, `projects/`, `servers/`, `widgets/`) that are used by the Express server.
- **`tests/`**: End-to-end tests (e.g., using Puppeteer or Vitest).
- **`server.js`**: The main entrypoint for the Express API which serves the built frontend and handles all backend routes.

## Data Flow
- **Frontend State**: Managed locally via React `useState` hooks since the application state is mostly isolated to specific views (projects list, terminal output, active widget data).
- **Backend Communication**: Components call the unified `apiFetch` wrapper (in `api.ts`) which automatically attaches JWT tokens.
- **Authentication**: JWT-based. The token is generated by the backend on login and stored in `localStorage`. 

## Performance Considerations
- **Build Optimization**: Configured in `vite.config.ts`. Source maps are disabled for production builds, and chunk sizes are monitored with a limit of 1000 kB.
- **Code Organization**: Unused states and variables have been pruned during linting. Strict TypeScript checks are applied for robust type safety on API responses and mocked data.
